# DP5q architecture and verification

CheckSI owns optional CPU DP5q calculation with bundled fixed parameters. Scores describe compatibility with original ¹³C observations under reported structural scope; they are advisory, not calibrated probabilities of identity. [Analysis](analysis.md) owns user applicability; [reports](reports.md) owns exported fields.

## Runtime boundary

`ApplicationRunner` copies effective settings, extracts/analyzes documents, and prepares requests before model readiness. Only eligible `CheckRequest` objects require asset/dependency validation. A lazy run-owned `DP5qSession` starts one isolated child, loads parameters once and serves serial compounds. Disabled, boron-only and no-eligible runs need no child. GUI metadata status never decides chemistry applicability.

The package dependency direction is contracts → client/worker → graph/geometry/network/scoring, with preparation/report adapters outside the numerical engine. The parent does not import native model arrays. Bounded finite JSON lines carry run/generation/sequence/compound identities; capped stderr is drained separately. Invalid local requests/results do not consume crash replacement. A failed compound is not retried; one replacement generation may serve later compounds after a crash. Startup failure/exhausted replacement produces explicit failures for remaining eligible compounds. A compound timeout retires that generation without consuming crash replacement. Cancellation starts no replacement.

Startup and full doctor checks have 120-second deadlines. Parent-alive cancellation permits two seconds cooperation, then bounded terminate/kill/reap. Owner death/protocol EOF arms a one-second worker exit grace before heavy native imports too. POSIX observes direct-parent replacement, blocks direct SIGINT and owns private process groups; Windows observes the actual owner through synchronization handles even through venv launchers. Protocol monitoring does not compete for stdin during native imports. Report findings use bounded explanations, not raw stderr.

Installed verification binds actual Windows interpreter/launcher identity and checks normal, cancelled and forced-launcher exits. Extraction/rendering may finish their current operation; [usage](usage.md#cli-run-and-cancellation) describes converter cancellation and residual-file limits.

## Calculation and applicability

Manifest identities are model `dp5q-cascade-owned-v1`, preprocessing `dp5q-spatial-v1`, score `dp5q-logtail-v1`, geometry `converged-single-v2`. Generate 30 deterministic ETKDGv3 candidates; if none embed, retry random starting coordinates with the same seed. MMFF94s uses 500 initial plus up to 1,500 continuation iterations. Only finite converged candidates preserving supported specified tetrahedral/double-bond stereo qualify; retain the lowest-energy compatible candidate.

Carbon-coordinate partition verification then compares original atom sets on existing coordinates. It is postselection evidence, never a conformer filter/scoring gate. Missing/mismatched proof stays unverified without re-embedding, methyl relabelling or arbitrary automorphism. Supported isotope-created ring E/Z beside exocyclic C=C uses those coordinates. Provenance retains coordinate/stereo verification limits and selected isomer; axial/atropisomer identity is unestablished.

Every boron structure is `not_applicable`/`boron_not_supported` before readiness/geometry. Producer, engine and host enforce no score/assignments; `dp5_boron_not_supported` visibility changes nothing. No UFF/xTB fallback, omission mask or boron partial score is supported. Independent carbon diagnostics retain the full inventory and justified absent direct-C–B sites: 1.147 retains 18 environments, 17 observations, absent C6/original atom 5. Remote/duplicate/symmetry-related sites cannot inflate allowance; measured C–B signals remain counted.

Exactly one carbon-bearing component in a non-boron disconnected source can be scored alone, preserving charge/protonation/observations; the warning explains ignored counter-ion/solvate and possible salt shifts. Multiple carbon-bearing components remain unscored with an Info note; no peak allocation occurs.

The NumPy network shares an encoder with separate mean/99-quantile heads. Only true-equivalent atom predictions/quantiles are averaged; distinct environments stay separate even with shared observations. Weighted squared-residual assignment retains the first optimum, including ties. Unsupported graph/elements are not applicable; nonidentifiable fits, invalid numbers/diagnostics and unexpected computation failures use `dp5_analysis_failed`, without score. Stable log-tail aggregation has no artificial epsilon floor and can differ substantially from legacy arithmetic. Refusal/failure/cancellation publishes no score. Engineering/reference fixtures prove their stated software comparisons, not independent chemical truth or training independence.

## Structural inventory and observation contract

Structure analysis supplies original-index partitions, completeness/reasons, configuration and typed meso status. Atom R/S, relative ring/coupled tetrahedral and bond E/Z roles remain distinct. Peak ratios/manual lower counts never establish meso/completeness. [Adjudicated fixtures](chemistry-verification.md) retain source-specific decisions.

Protocol 2 requires READY capability `coincident-observations-v1`. `CheckRequest` retains original-order `carbon_labels`, full `carbon_groups`, one shift per observation, `fixed_assignments`, and legacy-named `observation_atom_counts`. Explicit groups keep outer order; remaining carbons become original-order singletons. Fixed maps use group/original-observation indices; values are nonboolean integers. Only canonical decimal JSON keys normalize to integers; collisions fail.

`observation_atom_counts` expresses exact formal-environment capacities, not atom counts. `(2C)` is one observation covering two non-equivalent environments. Absent annotations are unknown; unannotated sharing needs justified disjoint `coincident_environments` coalitions in canonical group indices. Current coalitions cover supported isopropyl methyl cases. Every environment/observation must be covered; no public omission field/capability exists.

Sharing among k environments gives each weight 1/k; unique weight is 1. Total weight equals original observation count. Each environment retains its prediction/quantile fit. Population-mixed two-tail compatibilities aggregate by weighted geometric mean. Regression, conditioning, MAE and objective use the same weights: replicated rows cannot invent observations or correction availability. One observation has `insufficient_signals` for correction, though identity-fit compatibility is defined. Unit-weight spectra retain their meaning; shared spectra gain no calibration claim.

Generation allows 64 complete policies/Hungarian solves and 8,192 states, applying fixed maps/capacities/coalitions during generation; exhaustion refuses partial optimization. Shared weights multiply squared residuals once. A common finite cost scale prevents overflow without changing ranking. Exported objective is weighted absolute residual sum; raw MAE is weighted absolute mean, ppm. Equal optima keep the first solution without tie-refusal solves; differing quantiles can yield different scores despite identical means.

Incomplete source partitions permit a single embedding-selected form retaining source groups, reasons and `lowest-energy-embedded-isomer-v1`. Unsupported stereo remains unverified; complete requests also use postselection evidence. Scope warnings do not certify original source completeness. The host checks finite schema/model/source graph/component/supported stereo, original row labels/indices, fixed maps/capacities/weights and alias agreement. Worker-owned enumeration/partition/prediction/Gaussian fitting is not repeated by the host. [JSON](reports.md#json-v2) retains full inventory, observations, sharing, scope, provenance and separate fit locations/sigmas. Old omission/cardinality and coordinate-selection paths are removed.

## Configuration and retained files

[Configuration](configuration.md#schema-and-defaults) owns active fields, 20% fresh threshold, saved-value preservation and legacy aliases. Loads/confirmation never save; explicit persistence canonicalizes accepted inputs. External runtime directories remain untouched.

Successful opt-in retained artifacts contain finite `assessment.json` and `candidate.sdf` beneath the unique run directory: request/result, assignments, provenance, diagnostics, timings and geometry. No pickle/HDF5/executable model, external reference checkout, training, GPU or persistent prediction cache is needed. [Reports](reports.md#artifacts-and-ownership) owns filenames/status.
